# ドメイン環境での検証手順書

LapsTool 0.1.0-alpha をドメイン環境で検証するときの**操作手順だけ**をまとめる。
機能と仕組みの説明は [README](../README.md) を参照。

このドキュメントは「上から順に実施すれば検証が終わる」ことを目指す。
開発端末（ドメイン非参加）で確認済みなのは、ビルド・GUI の起動・資格情報の一時登録と削除・設定の書き出しだけ。
**AD・LAPS・RDP に関わる部分は、ここに書いた検証が初めての実機確認になる。**

---

## 0. 準備（最初に1回）

### 0-1. 検証環境

下の例（`test.local`）で書く。実際の環境に読み替えること。

| 役割 | 例 | 条件 |
|---|---|---|
| 操作端末 | `CL01` | ドメイン参加済み。Windows 11、または Windows 10（2023年4月以降の更新適用）。**ローカル管理者でないユーザーで作業する** |
| Windows LAPS（暗号化）端末 | `PC01` | Windows LAPS で、パスワード暗号化を有効にして管理している |
| Windows LAPS（平文）端末 | `PC02` | Windows LAPS で、暗号化を無効にして管理している（用意できなければ省略可） |
| 旧 LAPS 端末 | `PC03` | 旧 Microsoft LAPS（AdmPwd）で管理している（用意できなければ省略可） |
| LAPS 未管理端末 | `PC04` | LAPS の管理対象外 |

| アカウント | 例 | 権限 |
|---|---|---|
| 権限ありユーザー | `TEST\lapsadmin` | 参照権限・有効期限変更権限・暗号化パスワードの復号権限をすべて持つ |
| 権限なしユーザー | `TEST\user01` | LAPS の権限を何も持たない一般ユーザー |

LAPS で管理されているローカルアカウント名を確認しておく（例：`Administrator`、`LocalAdmin` など）。以下では **`<管理アカウント>`** と書く。

### 0-2. 正解の値を控える（比較用）

ツールの表示と比べるために、OS 標準のコマンドで現在の値を確認しておく。
権限ありユーザーの PowerShell で実行する。

```powershell
# Windows LAPS（PC01 / PC02）
Get-LapsADPassword -Identity PC01 -AsPlainText | Format-List ComputerName,Account,Password,PasswordUpdateTime,ExpirationTimestamp,Source
```

```powershell
# 旧 LAPS（PC03）。AdmPwd.PS モジュールが無ければ「Active Directory ユーザーとコンピューター」の属性エディターで確認する
Get-AdmPwdPassword -ComputerName PC03 | Format-List
```

> パスワードを画面に出すので、周囲に注意する。控えた値は検証後に破棄する。

### 0-3. ツールの配置

1. 開発端末で作った `dist\Release` フォルダから、次の3ファイルを操作端末の任意のフォルダ（例：`C:\Tools\LapsTool`）へコピーする。
   - `LapsTool.exe`
   - `LapsTool.exe.config`
   - `LapsTool.Core.dll`
2. 操作ログの場所を覚えておく：`%APPDATA%\LapsTool\logs\operations_yyyyMM.log`
3. 設定ファイルの場所：`%APPDATA%\LapsTool\settings.xml`（初回は存在しない）

## 検証A: 起動と設定

**目的**: 標準ユーザーのまま起動でき、設定の保存・読込・既定値ファイルが機能すること。

1. 権限ありユーザーでサインインし、`LapsTool.exe` をダブルクリックする。
2. ［設定…］を開き、次のように変更して［OK］を押す。
   - ローカルアカウント名：`<管理アカウント>`
   - 一時資格情報を削除するまで：`3`（範囲外の値）
3. ツールを閉じて、もう一度起動する。［設定…］を開いて値を確認する。
4. ［既定値ファイルとして書き出す…］で、`LapsTool.exe` と同じフォルダに `LapsTool.defaults.xml` を保存する。
5. `%APPDATA%\LapsTool\settings.xml` を削除してから起動し、［設定…］を開く。

**期待結果**:
- 手順1で UAC の昇格ダイアログが**出ない**。
- 手順3でローカルアカウント名が保持されている。削除までの秒数は `5` に補正されている（下限が5秒のため）。
- 手順5で、既定値ファイルの値（`<管理アカウント>`）が初期値として表示される。

確認が終わったら、削除までの秒数を `20` に戻す。

## 検証C: Windows LAPS のパスワード参照

**目的**: 暗号化・平文の両方で正しいパスワードが取れ、表示・コピーが仕様どおり動くこと。

1. PC01 を選び、［取得］を押す。
2. ［表示］を押す。もう一度押す（「隠す」になっている）。
3. ［コピー］を押し、メモ帳に貼り付ける。そのまま**35秒**待ち、もう一度貼り付ける。
4. もう一度［コピー］を押し、10秒以内に**別の文字列**をコピーする。35秒待ってから貼り付ける。
5. PC02（平文）でも手順1〜2を行う。

**期待結果**:
- 手順1：伏せ字（●）で表示される。アカウント・最終更新・有効期限が 0-2 の値と一致する。
- 手順2：0-2 で控えたパスワードと一致する。もう一度押すと伏せ字に戻る。
- 手順3：1回目は貼り付けられる。35秒後は何も貼り付けられない（クリップボードが消去されている）。
- 手順4：手順4で自分がコピーした文字列が貼り付けられる（**ツールは利用者がコピーした内容を消さない**）。
- 手順5：PC02 のパスワードも 0-2 と一致する。

## 検証E: 権限が無い場合

**目的**: 権限の無い操作が AD 側で拒否され、分かるメッセージが出ること。

1. 権限なしユーザー（`TEST\user01`）でサインインし、ツールを起動する。
2. PC01 を検索し、［取得］を押す。
3. PC03 で［取得］を押す（用意できる場合）。
4. PC01 で［今すぐ期限切れにする］→［OK］を押す。

**期待結果**:
- 手順2：パスワードは表示されず、権限が無い旨のメッセージが出る（暗号化端末では「DecryptionStatus」を含むメッセージになることがある）。
- 手順3：「参照権限が無いか、まだパスワードが設定されていません。」と表示される。
- 手順4：有効期限は変わらず、権限が無い旨のメッセージが出る。
- いずれの場合もツールが落ちず、そのまま操作を続けられる。

**補足**（可能であれば）: 参照権限はあるが**復号権限だけが無い**ユーザーでも PC01 を試し、パスワードが表示されないことを確認する。

## 検証G: 有効期限の変更（Windows LAPS）

**目的**: 有効期限を指定どおりに書き換えられ、実際にパスワードがローテーションされること。

1. 権限ありユーザーで PC01 を選び、［取得］を押して現在のパスワードを控える。
2. 日付に**3日後**、時刻に `09:00` を入力し、［この日時に変更］→［OK］を押す。
3. 時刻に `25:00` を入力し、［この日時に変更］を押す。
4. ［今すぐ期限切れにする］→［OK］を押す。
5. PC01 にサインインし、管理者として PowerShell で次を実行する（ポリシー処理を待たずにローテーションさせる）。

   ```powershell
   Invoke-LapsPolicyProcessing
   ```

6. ツールに戻り、PC01 を検索し直して［取得］→［表示］を押す。

**期待結果**:
- 手順2：確認ダイアログに指定した日時が表示される。変更後、有効期限の表示と一覧が3日後の 09:00 になる。0-2 のコマンドで見た `ExpirationTimestamp` も一致する。**取得済みのパスワード表示は消えない。**
- 手順3：「有効期限の日付と時刻（HH:mm）を正しく入力してください。」と表示され、何も変わらない。
- 手順4：有効期限が現在時刻になり、「（期限切れ・次回ポリシー処理で更新）」と表示される。
- 手順6：パスワードが手順1と**変わっている**。最終更新が手順5の時刻になり、有効期限が新しい値（ポリシーで定めた日数後）になっている。

## 検証H: 有効期限の変更（旧 LAPS）

PC03 を用意できない場合は省略する。

1. PC03 で、検証Gの手順1〜2と同じ操作をする。
2. 「Active Directory ユーザーとコンピューター」で PC03 の `ms-Mcs-AdmPwdExpirationTime` 属性を確認する。
3. ［今すぐ期限切れにする］→［OK］を押す。
4. PC03 で管理者のコマンドプロンプトから `gpupdate /force` を実行する。
5. ツールで PC03 を検索し直して［取得］→［表示］を押す。

**期待結果**:
- 手順1：表示上の有効期限が指定した日時になる。
- 手順2：属性の値が指定した日時と一致する。
- 手順5：パスワードが変わっている。

## 検証I: リモートデスクトップ接続

**目的**: パスワードを入力せずに接続でき、一時登録した資格情報が確実に消えること。

事前準備:
- PC01 でリモートデスクトップ接続が有効で、`<管理アカウント>` が RDP でサインインできること。
- 操作端末で別の PowerShell ウィンドウを開いておく（資格情報の確認用）。

### I-1. 基本の接続

1. PC01 を選び、［取得］は押さずに［接続］を押す。
2. mstsc が起動したら、**すぐに** PowerShell で次を実行する。

   ```powershell
   cmdkey /list:TERMSRV/pc01.test.local
   ```

3. 20秒以上待ってから、もう一度同じコマンドを実行する。

**期待結果**:
- 手順1：パスワードが自動で取得され、パスワード入力なしで PC01 に `<管理アカウント>` としてサインインできる。
- 「リモートデスクトップ」欄に `pc01.test.local に PC01\<管理アカウント> で接続` と表示される。
- 手順2：ユーザー `PC01\<管理アカウント>`、種類「ドメイン パスワード」、「このログオンのみ保存」の資格情報が表示される。
- 手順3：「* NONE *」と表示される（削除されている）。

### I-2. アカウント名の設定

1. ［設定…］で「Windows LAPS に記録されたアカウント名を優先する」を**オフ**にし、ローカルアカウント名を存在しない名前（例：`dummyuser`）にする。
2. PC01 で［接続］を押す。
3. 設定を戻す（優先をオン、アカウント名を `<管理アカウント>` に）。
4. 優先を**オン**のまま、アカウント名だけを `dummyuser` にして［接続］を押す。

**期待結果**:
- 手順2：接続表示が `PC01\dummyuser` になり、サインインに失敗する（設定値が使われている）。
- 手順4：接続表示が `PC01\<管理アカウント>` になり、サインインできる（LAPS に記録された名前が優先されている）。
- PC03（旧 LAPS）では、優先のオン・オフにかかわらず、常に設定値のアカウント名が使われる。

確認が終わったら、ローカルアカウント名を `<管理アカウント>` に戻す。

### I-3. 接続オプション

| # | 設定 | 期待結果 |
|---|---|---|
| I-3-1 | 「FQDN で接続する」をオフ | 接続先が `PC01` になる。`cmdkey /list:TERMSRV/PC01` で一時資格情報が確認でき、接続できる |
| I-3-2 | 「管理モード（/admin）」をオン | タスクマネージャーの「詳細」タブで、mstsc のコマンドラインに `/admin` が付いている |

### I-4. 既存の資格情報がある場合

1. PowerShell で、PC01 向けの資格情報を**ダミーで**作る。

   ```powershell
   cmdkey /add:TERMSRV/pc01.test.local /user:PC01\dummy /pass:dummy-value
   ```

2. ツールで PC01 の［接続］を押し、確認ダイアログで［キャンセル］を押す。
3. もう一度［接続］を押し、今度は［OK］を押す。20秒待ってから `cmdkey /list:TERMSRV/pc01.test.local` を実行する。

**期待結果**:
- 手順2：上書きの確認が出る。キャンセルすると mstsc は起動せず、ダミーの資格情報は残っている。
- 手順3：接続でき、20秒後には資格情報が「* NONE *」になる。

### I-5. 後始末の確実さ

1. ［接続］を押し、mstsc が起動したら**20秒以内に**ツールを閉じる。`cmdkey /list:TERMSRV/pc01.test.local` を実行する。
2. ツールを起動し直す。［接続］を押し、10秒後にもう一度［接続］を押す。最初の接続から20〜30秒の間に `cmdkey /list` を実行する。

**期待結果**:
- 手順1：ツールを閉じた時点で資格情報が消えている。
- 手順2：2回目の接続の資格情報が、最初のタイマーで**消されずに残っている**。2回目から20秒後に消える。

### I-6. 保存資格情報がポリシーで使えない環境（該当する場合のみ）

1. 「接続時に常にパスワードを要求する」が有効な端末に［接続］を押す。
2. ［設定…］で「接続時にパスワードをクリップボードにもコピーする」をオンにし、もう一度［接続］を押す。

**期待結果**:
- 手順1：mstsc がパスワードの入力を求める（ツールのエラーではない）。
- 手順2：パスワード欄に貼り付けて接続できる。クリップボードは30秒後に消去される。

## 検証J: 別アカウントで起動（runas /netonly）

1. 権限なしユーザーでサインインした端末で、コマンドプロンプトから次を実行する。

   ```bat
   runas /netonly /user:TEST\lapsadmin "C:\Tools\LapsTool\LapsTool.exe"
   ```

2. PC01 と PC03 で［取得］を押し、PC01 で［接続］を押す。

**期待結果**:
- パスワードを取得できる（AD へは `lapsadmin` で認証されている）。
- 接続できる（一時資格情報は、サインインしているユーザーのセッションに登録される）。

> 暗号化パスワードの復号が `/netonly` で通るかは**未確認の論点**。失敗した場合は、エラーメッセージをそのまま記録する。

## 検証K: 操作ログ

1. ここまでの検証を終えたら、`%APPDATA%\LapsTool\logs\operations_yyyyMM.log` を開く。
2. 検証C で控えたパスワードの文字列で、ログを検索する。

   ```powershell
   Select-String -Path "$env:APPDATA\LapsTool\logs\*.log" -SimpleMatch "<控えたパスワード>"
   ```

**期待結果**:
- 「パスワード参照」「パスワードコピー」「有効期限変更」「RDP接続」の各行がある。各行に日時・実行ユーザー・端末名・結果（成功・失敗の理由）が入っている。
- 検証Eの失敗が「失敗: …」として記録されている。
- 手順2の検索で**何もヒットしない**（パスワードはログに残らない）。
